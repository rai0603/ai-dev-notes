◆ 02 / Curriculum

10 堂課的核心主題與教學目標

每堂都包含「核心主題、教學目標、真實案例」三段。真實案例全部來自我自己上線的專案，不是教科書範例。

L1 ⏱ 20 min · 入門

為什麼現在是最好的時機 — Vibe Coding 的世界觀

核心主題

從「程式工人」到「方向決定者」的角色轉變。你不是在學寫 code，是在學指揮 AI 寫 code。

教學目標

學員能說出 Vibe Coding 三要素（電腦、耐心、好奇心），並理解為什麼非科班出身的人現在反而更有優勢。

真實案例
  • 水行者預約系統 2 天上線、十年 WooCommerce 對比
  • 同一個問題用傳統開發 vs Vibe Coding 的時程差
  • 省下 NT$50,000 + 十年心智耗損的真實財務影響
#心理門檻 #非科班 #工程師角色重定義
L2 ⏱ 25 min · 入門

你的開發分身 — Claude Code 工具鏈基礎設施

核心主題

把 AI 變成「會記得你怎麼工作」的協作者。一份好的 CLAUDE.md，能讓 AI 從工具變成分身。

教學目標

學員能寫出第一份全域 CLAUDE.md，並理解 skill / subagent / MCP 各自扮演什麼角色、什麼時候該用哪一個。

真實案例
  • Rai 自己的 CLAUDE.md「開發分身 Manifesto」三段結構（身份 → 原則 → 偏好）
  • 用 feedback memory 讓 AI 不會把同一個錯誤犯第二次
  • MCP 連 Supabase / GitHub 的真實效率差
#CLAUDE.md #skill #MCP #API key 安全
L3 ⏱ 30 min · 入門

思考協議 — 從「我想做一個 XX」到可執行規格

核心主題

用四階段協議把模糊願望變成 AI 能執行的工作項。不要讓 AI 一上來就寫 code，先把問題聊清楚。

教學目標

學員能對任何新需求跑完 Phase 1 (釐清) → Phase 2 (架構) → Phase 3 (規格) → Phase 4 (實作) 的協議流程。

真實案例
  • 現場示範：把「我想做一個寵物社群」跑完四階段
  • 用 AI 挑戰自己的隱性假設（避免 AI 一味迎合）
  • 三方案比較 vs 直接做的取捨
#MVP 邊界 #YAGNI 煞車 #需求拆解
L4 ⏱ 25 min · 新手

開新專案的第一個小時 — 目錄、CLAUDE.md、基線

核心主題

每個專案要有的開場儀式，省下後面 80% 的重來。架構在第一個小時決定，不是在第一百個小時。

教學目標

學員能在 60 分鐘內建好新專案的目錄分層、專案 CLAUDE.md、.env.example、Git 基線。

真實案例
  • Controller → Service → Repository 三層的具體檔案結構
  • TypeScript 嚴格 + Zod 驗證 + Result Pattern 的最小範本
  • DiDiPo / AICMS 的開頭設定對照
#禁用 any #Result Pattern #專案 CLAUDE.md
L5 ⏱ 30 min · 新手

前端落地 — 從零到能點的 MVP 介面

核心主題

Vite + React + Tailwind + shadcn/ui 為何是最快組合，以及怎麼跟 AI 描述介面才不會生出醜東西。

教學目標

學員能用結構化方式描述 UI 需求，做出響應式、深色模式、動畫流暢的頁面。

真實案例
  • DiDiPo 儀表板 7-Tab 帳號管理頁的拆解
  • AICMS admin UI 的元件複用策略
  • ai-match 名片頁用 ISR 砍 90% Supabase egress
#shadcn/ui #a11y #ISR #深色模式
L6 ⏱ 30 min · 新手

後端落地 — Supabase 為何是 80% 個人專案最佳解

核心主題

Auth + RLS + Edge Functions + Storage 一站式的設計與陷阱。為什麼「讀靠 RLS、寫靠 API + service role」是穩定策略。

教學目標

學員能規劃出一份權限分層清楚的 Supabase 架構，並避開 RLS 與業務邏輯混在一起的常見陷阱。

真實案例
  • ai-match 多名片功能的 RLS 設計
  • DiDiPo Edge Function 部署 SOP（含 --no-verify-jwt 為什麼是預設）
  • Supabase 新版 API key 遷移（sb_publishable_ / sb_secret_）— 沒換掉會讓 OAuth 全炸
#Supabase #RLS #Edge Functions #新版 API key
L7 ⏱ 25 min · 新手

部署 — 免費起步 → 付費階梯

核心主題

GitHub Pages / Cloudflare Pages / Zeabur 的選擇樹，以及真實月費結構。不要一開始就花錢，但也要知道什麼時候該花。

教學目標

學員能根據專案類型（純前端 / SSR / Next.js）選對部署平台、估算出大致月費。

真實案例
  • 9 個專案的部署對照表（GitHub Pages / Zeabur / Cloudflare Pages）
  • 為什麼選 Zeabur 不選 Vercel（地理位置 + 定價模型）
  • CF Pages Functions 在 Zeabur 是死碼 — 一個我踩過才知道的陷阱
#GitHub Pages #Cloudflare #Zeabur #月費結構
L8 ⏱ 30 min · 中階

AI 寫的 code 卡住時 — 8-Step Bugfix Protocol

核心主題

禁止「沒 failing test 就 patch」。把 debug 變成可重複的 SOP，避免你跟 AI 一起在錯誤的方向上越跑越遠。

教學目標

學員遇到 bug 時能跑完 8 步：最小重現 → failing test → 根因 → 最小修復 → regression → spec → review → report。

真實案例
  • SPA Fallback 誤判存在（fetch llms.txt 回 200 但其實是 index.html）
  • Supabase Edge Function OAuth 401（部署要加 --no-verify-jwt）
  • OAuth Callback 跳 localhost（Zeabur reverse proxy 要讀 x-forwarded-host）
#Bugfix Protocol #failing test #不要順手重構 #scope 控制
L9 ⏱ 30 min · 中階

上線之後 — 從 0 用戶到 100 用戶的觀察與商業化判斷

核心主題

產品上線只是起點。怎麼跟真實使用者互動、收 feedback、決定何時開始收錢，這堂講完。

教學目標

學員能規劃 analytics、設計 feedback channel、判斷自己的產品有沒有走到「該收費」的時機點。

真實案例
  • AICMS 自建 Analytics（per-tenant + 跨站 + 縣市 + 退出頁）取代 GA4
  • CitableRank AI 客服 widget + LINE 真人轉接
  • 金流四連坑決策樹：藍新（卡 1 個月）→ Stripe（台灣無法）→ Lemon（拒 SaaS）→ Paddle（最終解）
  • Paddle webhook subscription.canceled 沒 current_billing_period 的防禦
#Analytics #Paddle #Meta App Review #in-app browser #feedback channel

1→N — 把 side project 做成可累積的資產

核心主題

為什麼要持續做？怎麼把每個專案變成下一個的素材。你的品牌就是你的踩坑紀錄。

教學目標

學員理解「品牌＝踩坑紀錄」的長線邏輯，並能設計自己的 cross-project learning 系統。

真實案例
  • ai-dev-notes 的敘事演化（30 天 3 產品 → 9 產品）
  • sync-learnings 自動歸納跨專案經驗

  • 從個人 (零時生存) → B2C (ai-match) → B2B (CitableRank、AICMS) 的演化

◆ 04 / FAQ

常見問題

開始前你可能會想知道的事。

這門課適合誰？

想用 AI 加速做產品的人 —— 不論你是工程師、PM、設計師、創業者，還是完全的程式新手。有好奇心比有程式知識更重要。本課程不會教你 if/else 語法，會教你怎麼把模糊想法變成可上線的東西。

完全不會寫程式可以學嗎？

可以，但建議你願意花時間「看懂」AI 寫出來的程式碼在做什麼。本課程不要求你動手寫，但要求你能判斷對錯—— 這也是 Vibe Coding 的核心能力。

需要先安裝什麼工具？

最低配置：一台電腦（Mac / Windows / Linux 都行）、Claude Code CLI、一個文字編輯器（VS Code 或 Cursor）。第 2 堂課會帶你一步步裝起來。

技術棧有限制嗎？

課程以 TypeScript / React / Supabase 為主軸（我自己的主力技術），但方法論本身與技術棧無關。你用 Python / Go / Rust 也能套同樣的思考協議與 bugfix SOP。

看完 10 堂課我能做出什麼？

一個能上線的最小可行產品（MVP）。可能是個人工具、給朋友用的小服務、或自家事業的內部系統。重點不是「做出 SaaS 帝國」，而是從 0 到 1 走完一次完整流程，把那條路徑刻進你的肌肉記憶。
